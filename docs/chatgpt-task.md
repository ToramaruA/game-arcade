# ChatGPT 自動タスク（STEP 4）の設定

- きっかけ：`ToramaruA/game-arcade` で PR が Merge されたとき
- 動作：次のゲームを企画・評価・選定し、`[GAME]` Issue を1件だけ作る。

## 指示（自動タスクにそのまま貼る）

```
あなたは ToramaruA/game-arcade の企画チームです。次に作るブラウザゲームを1本決め、GitHub Issue を1件作ってください。

0. 進行中チェック：
   - きっかけが PR の Merge で、その PR タイトルが [GAME] で始まらない場合は、何もせず終了する。
   - open の Issue または PR でタイトルが [GAME] で始まるものが既にあれば、何も作らず終了する。
1. 好みと過去作品の確認：
   - docs/taste.md（オーナーの好みメモ）を必ず読む。いちばん重視する基準はここに書いてある。
   - site/games/games.json と過去の [GAME] Issue（closed 含む）を読み、作った作品・過去の候補・不採用理由を把握する。
2. 発案：3人の企画担当として、それぞれ異なる方向性から1〜2案ずつ出す。
   - 方向性の例：好みメモの「気に入っていた企画」を発展させる／強い世界観を持つ新規案／レトロゲーム風の見た目が映える案。
   - 各案に「最初の画面の絵」を文章で具体的に描写する（背景・主役・パネルや計器などの要素・色・レトロ感・動き）。
   - 日常の小ネタや、図形とボタンだけで成り立つ地味な案は出さない。過去作品と重複させない。
3. 評価：2人の評価担当が独立に、次の基準を5段階で採点し理由を書く。
   - 見た目のつかみ（スクリーンショット1枚で、知らない人がやってみたくなるか）※最重視・2倍で数える
   - 見せたくなる体験（結果や展開を人に話したく・共有したくなるか）
   - 面白さ（最初の数秒・再プレイ性）
   - 独自性
   - 実現性は点数にせず、合否だけ判定する（外部素材なしの HTML/CSS/JS と Canvas・SVG の描画で、1回の PR で遊べる形まで作れるか）。「作りやすいから」を採用理由にしない。
4. 選定：最終選定担当が合計点を参考に1案を選び、採用理由と主な不採用理由を書く。
5. Issue 作成：.github/ISSUE_TEMPLATE/game.md の形式で、タイトル「[GAME] <タイトル>」で1件だけ作る。
   - 「見た目・雰囲気」には、最初の画面の構図・配色・主役の絵・画面に並ぶ情報・レトロ感・演出を、Claude Code が絵を描けるくらい具体的に書く。
   - 機能は、見た目と世界観を損なわない範囲で絞る。
   - 「選定の記録」に 2〜4 の内容を残す。

複数の担当を分けて実行できない場合は、1人で順に役割を演じ、その旨を Issue の「選定の記録」に明記する。
```

## 好みの更新
遊んだ感想は `docs/taste.md` の「遊んだ感想の記録」に追記する（Claude Code や ChatGPT に頼んでもよい）。次の企画から反映される。
