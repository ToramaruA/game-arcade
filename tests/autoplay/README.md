# 自動プレイヤー（ゲームごと）

ゲームを作ったら、`tests/autoplay/<slug>.mjs` に自動プレイヤーを置く。
`npm run autoplay -- <slug>` で戦法ごとの勝ち数を表にし、`npm test` で最低限の約束を確かめる。
ゲームのルールは毎回違うので、自動プレイヤーはゲームごとに書く（共通なのは下の形と、表を出すコマンドだけ）。

## 標準の形（おすすめ）：操作の一覧を書けば、共通の自動プレイヤーが遊ぶ
`export const game = { ... }` を書くと、`tests/autoplay/lib/players.mjs` の共通の自動プレイヤーが次の戦法を自動で組み立てる。
- でたらめ（naive）
- 核を使わない遊び方を、よく考えて遊ぶ（naive。`naive` に書いた操作の絞り方ごと）
- 初心者・上級者（core。MCTS＝モンテカルロ木探索の、考える回数の違い）

放置で勝てないことが仕様上重要なゲーム（例：防衛ゲーム）だけ、`testNoop: true` を追加すると「何もしない（noop）」も検証する。手動操作なしでは状態が変わらないパズルなどに強制しない。`idle(state)` は他の戦法でも使うため維持する。

ゲームごとに書くのは「今できる操作」「操作したら進める」「勝ち負け」「途中の有利さ」と、核を使わない遊び方の絞り方だけ。
形の詳しい説明は `tests/autoplay/lib/players.mjs` の先頭、例は `tests/autoplay/lib/toy-game.mjs`（動作確認用の小さなゲーム）。

```js
export const game = {
  stages: [{ id: 0, name: '第1面' }, ...],
  start(stage, seed) { ... },        // 乱数の状態も state に入れる（clone したとき同じ続きになるように）
  actions(state) { return [...] },   // 今できる操作（「何もしない」も含める）
  idle(state) { return 'wait' },
  apply(state, action) { ... },      // 操作して、次に判断する時点まで進める
  result(state) { return 'win' | 'lose' | null },
  score(state) { return 0..1 },      // 途中の有利さ（耐久・残りの敵・進み具合など）
  naive: { redOnly: { name: '赤だけ置く', allow: (s, a) => ... } },
  levels: { beginner: 30, expert: 300 },  // 考える回数（重いゲームは減らす）
};
```

- **判断の区切りを決める**：ターン制ならそのまま1手。時間で進むゲームは「波の合間」「0.5秒ごと」など、判断する時点で区切り、`apply` でその時点まで時間を進める。
- **操作の数を絞る**：同じ意味の操作はまとめる（例：塔を置ける台座のうち、道に近い上位いくつかだけ）。多すぎると MCTS が考えきれない。
- **1回の play を数秒以内に**：重ければ `levels` の回数や `rolloutDepth`（先読みの深さ）を下げる。

- **乱数のないパズルは `key(state)` も書く**（同じ局面なら同じ文字列）。`npm run autoplay` が全部の手を調べて、次を正確に出す。
  - 各面の最短手数と、核を使わない遊び方（`naive` の絞り方）で解けるか・何手かかるか。
  - 難しさの目安（最短手数は「長さ」で「難しさ」ではないため）：
    - **詰む局面**：最短手数以内でたどり着く局面のうち、もう解けない割合。
    - **でたらめで解ける**：でたらめに動いて、最短の3倍以内に解ける割合。
    - **落とし穴**：最短の道の上で、その一手で詰む手がある場面の数。
  - MCTS は先の長いパズルが苦手で、人より弱く出る。核を使わない戦法も、操作が少ないぶん有利に出る。そのため、パズルでは MCTS の表は「参考」として出し、OK/NG は全部の手を調べた結果だけで出す。
  - 局面が多すぎる面（200万を超える）は、難しさを「—」と出す。

標準の形にできないゲーム（反射神経が主のアクションなど）は、下の「自由な形」で書く。

## 自由な形

```js
// ステージ（面・夜・章など）。name は表に出す名前
export const stages = [{ id: 0, name: '第1夜' }, ...];

// 戦法。naive と core はそれぞれ1つ以上。noop は必要な場合のみ。
//   noop  … 放置で勝てないことが仕様上重要な場合だけ追加（最低限の進行操作を含めてもよい）
//   naive … 1つの戦法だけ・でたらめ など、遊びの核を使わない遊び方
//   core  … 遊びの核を使う遊び方（Issue の「遊びの核」で考えて決める判断をする）
export const strategies = [
  // { id: 'noop', name: '何もしない', kind: 'noop' }, // 必要な作品のみ
  { id: 'redOnly', name: '赤だけ', kind: 'naive' },
  { id: 'full', name: '網目＋合図', kind: 'core' },
];

// 1回遊ぶ。同じ (stage, strategy, seed) なら同じ結果になること（乱数は seed から作る）
// 戻り値：{ win: boolean, score?: number, note?: string }
export function play(stage, strategy, seed) { ... }
```

- ルールは `logic.js`（DOM なし）にあるので、ブラウザなしで速く何度も遊ばせられる。
- 1回の `play` は1秒以内を目安にする（表を作るのに 面の数 × 戦法 × 回数 だけ呼ぶ）。
- 自動プレイヤーは上手でなくてよい。「戦法の違いで勝ちやすさがどう変わるか」を比べるためのもの。

## 見るところ（`npm run autoplay` が判定も出す）
判定の基準値は `scripts/autoplay.mjs` の `RULES` に1か所でまとめてある。

どのゲームでも：
1. **何もしないで勝てる面がない**（noop を明示的に指定した作品のみ確認する。あれば、その面は遊ばなくても終わる）。
2. **1つの戦法だけでほとんど勝ててしまわない**（naive の勝率が 75% 以上なら NG）。
3. **遊びの核を使うほど勝てる**（core の勝ち数が naive より多く、その差が偶然の範囲ではない。z 検定で片側 95%）。差が小さいときは「偶然の範囲」と出るので、`--runs` を増やして測り直す。
4. **試作の面（最初の2面）のどこかで核が要る**（試作で遊んでもらう面で、核の面白さが伝わるように）。
5. **最初の面は初心者でも半分以上勝てる**。

標準の形のときは、さらに次も見る：
- **上達の余地**：上級者が初心者より勝ち、その差が偶然の範囲ではない。
- **手応え**：後半の面は上級者でも全勝しない。
- **操作の回数**：1回のプレイで上級者が平均5回以上操作する（少なければ、眺めている時間が長いかもしれない）。

乱数のないパズル（`key` があるとき）は、全部の手を調べた結果で次を見る（上の 2〜5 と上達・手応えは「参考」になる。1 は noop を指定したときだけ、そのまま判定する）：
- **全部の面が解ける**。
- **核を使わない遊び方では、解けない・遠回りになる面が半分以上ある**（少なければ、その仕組みは飾りになっている）。
- **試作の面（最初の2面）のどこかで、核を使わないと解けない・遠回りになる**。
- **後半の面は、でたらめでは半分も解けない**。
- 最初の面で詰む局面が半分を超えたら「注意」（入り口でやり直しが多い）。

自由な形のときは、core の戦法がこのゲーム用に書いた戦法なので、作り手の想定した解き方しか測れない。PR の表の下にそう書く。

## 速さ
`npm run autoplay` は CPU の数だけ並列で遊ぶ（`--jobs 1` で並列にしない）。並列でも同じ seed なら同じ表になる。
